# KOL Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Deliver a working Windows tray clipboard history app and publish its source to a new public KOL repository.

**Architecture:** Go Win32 capture and tray, embedded WebView2 panel, encrypted bbolt metadata and payload buckets. Clipboard transport, history and UI have independent boundaries.

**Tech Stack:** Go 1.26+, x/sys/windows, bbolt, go-webview2, plain HTML/CSS/JavaScript.

**Spec:** `docs/superpowers/specs/2026-10-28-kol-design.md`

## Global Constraints
- Windows 10/11; `%LOCALAPPDATA%\KOL`; no runtime network requests.
- Exact supported bytes; no whitespace normalization; stable named-format identity.
- No count/time retention by default; 64 MiB item limit adjustable.
- AES-256-GCM data, DPAPI key; opt-in login startup; partial formats visible.
- Public repository `nRudzy/KOL` authorized by user; no personal clipboard data in source or screenshots.

## Review Focus
- Clipboard contention and fast consecutive copies: bounded retries and coherent sequence checks.
- Rich text with equal plaintext: distinct identity; no destructive shell move metadata replay.
- Corrupt encrypted storage: explicit failure; never silently reset or overwrite a key.
- Hostile copied HTML/text: display with textContent and no remote content loads.
- Multi-monitor/high DPI and Explorer restart: panel stays in work area, tray icon returns.
